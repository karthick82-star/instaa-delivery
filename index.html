Instaa Core Engineering Features

Implementation of the complete rural hyperlocal Q-commerce ecosystem architecture.

Feature 1

1. The King & Queen HA

Secondary standby server (QUEEN - GCP Bangalore) automatically detects primary server (KING - AWS Mumbai) outages with zero manual intervention. Continuous 3s heartbeat ping, zero shared infrastructure, and instant SMS alerts to admin.

Open HA Server Monitor →
Feature 2

2. The Neighbors

Shops have online/offline toggling. If all shops of Town A are offline, customer gets a popup to order from Town B with an inter-town delivery fee (₹70, 45-60 mins). Respective town riders get priority assignment.

Test Neighbor Town Flow →
Feature 3

3. Time Out (2-Min Idle)

After an order is assigned, the backend monitors rider geolocation. Because there are no traffic lights in rural towns, an idle rider (> 2 mins) has their order automatically reassigned to another rider with instant alert modal.

Test Idle Reassignment →
Feature 4

4. Varying Commission Slabs

Commissions vary per category: Kitchen Staples (3-4%), Dairy & Daily Essentials (3-5%), Packaged FMCG & Snacks (6-8%), Personal Care & Household (8-10%). Virtual ledgers deduct itemized rates. Admin can edit rates anytime.

View Commission Slabs →
Feature 5

5. App to App Handshake

Proceeding to pay opens the installed payment app (Google Pay) via UPI deep link intent. Cart value is auto-typed into GPay with direct settlement into Instaa Admin Bank Account.

Inspect GPay Handshake →
Feature 6 & Cases

6. Built-in GMap & Damaged Return

Rider has an inbuilt map automatically loaded with customer destination. Case i: No damage & OTP verified. Case ii: Damaged item returned to store, deducted from store deposit, rider pay released, customer refunded in 1-2 days.
